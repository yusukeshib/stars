# Catalog backend scaling design

This page closes roadmap item `L-16` (legacy `P3-00`): it defines the catalog seams that must be
stable before adding Hipparcos, Tycho-2, Gaia DR3, or larger deep-sky datasets.
The current implementation remains HYG-backed, but `crates/catalog` now exposes
minimal backend scaffolding so future ingest work extends an API instead of
rewriting host/rendering paths.

## Goals

- Preserve deterministic small builds: HYG CSV remains the native default and
  the compact embedded HYG subset remains the WASM / single-binary path.
- Make source identity explicit: every backend reports a `CatalogSource` with a
  stable backend kind, human source name, and version.
- Preserve numeric identifiers early: `Star` rows can now carry HYG,
  Hipparcos, HD, Tycho-2, and Gaia DR3-style numeric identifiers without
  changing renderer buffers yet.
- Separate source filtering from display exposure: catalog queries use
  `CatalogQuery::max_magnitude`; renderer limiting magnitude remains a visual
  observer/exposure control.
- Leave room for large-catalog paging and LOD: `CatalogPage` has `truncated` and
  `next_page` fields even though HYG currently returns a single page.

## Implemented scaffold

`crates/catalog/src/backend.rs` defines:

- `CatalogBackend` — trait implemented by catalog providers;
- `CatalogBackendKind` — stable backend labels such as `hyg-csv` and
  `hyg-embedded`;
- `CatalogSource` — backend/source/version metadata for snapshots and future
  manifests;
- `CatalogObjectId` and `CatalogIdentifiers` — numeric cross-ID storage for
  HYG, HIP, HD, Tycho-2, and Gaia DR3 identifiers;
- `CatalogQuery` — source-side filters, currently `max_magnitude` and optional
  `max_rows`; the HYG adapter keeps the historical repository-wide m≤8 cap and
  lets queries narrow that set further;
- `CatalogPage` — one page of stars plus source/query metadata;
- `HygCsvBackend` — filesystem-backed HYG adapter used by the legacy
  `load_from_file` compatibility function;
- `HygEmbeddedBackend` — embedded compact-HYG adapter for WASM / single-binary
  builds.

The public `Star` struct now includes `identifiers: CatalogIdentifiers`. The
existing renderer and host conversion paths keep ignoring those identifiers
until `L-18` (legacy `P3-02`) wires ID-aware hover/copy/session behaviour through the renderer.

## Backend boundaries

A backend is responsible for:

1. reading or opening its source artifact;
2. applying source-side filters from `CatalogQuery`;
3. converting rows into the engine's canonical `Star` fields:
   - J2000-like unit direction;
   - distance in parsecs when known;
   - Cartesian proper-motion tangent vector in radians per Julian year;
   - apparent visual magnitude;
   - display input colour;
   - available numeric identifiers;
4. returning deterministic pages for a fixed query and data source.

A backend is **not** responsible for:

- renderer limiting magnitude or tone mapping;
- per-frame apparent-place corrections;
- UI hover state or external service links;
- downloading remote services at render time.

## Identifier policy

- HYG rows use HYG ID as `primary` when present and retain HIP / HD cross-IDs.
- Tycho-2 and Gaia DR3 ingest should use their native numeric IDs as primary for
  rows whose source is those catalogs.
- Cross-match tables should fill the optional fields instead of replacing the
  source's primary ID.
- Renderer buffers should receive compact numeric IDs only after `L-18` (legacy `P3-02`) defines
  hover/click/session requirements; until then IDs stay CPU-side in `catalog`.

## LOD, paging, and spatial index plan

Large catalogs should not be uploaded as one monolithic star array. Future
backends should add these pieces behind `CatalogBackend`:

1. **Magnitude tiering** — always load a bright all-sky tier first, then page
   fainter stars based on projection, field of view, and display scale.
2. **Spatial indexing** — store rows in HEALPix-style or fixed spherical-cell
   tiles so all-sky projections and telescope fields can request bounded cells.
3. **Stable ordering** — sort by source ID inside a tile, and by brightness for
   top-N fallbacks, so notebook/session outputs remain diffable.
4. **Page cursors** — use `CatalogPage::next_page` for deterministic continuation
   tokens when a query is truncated.
5. **Renderer upload batches** — translate pages to `StarInstance` batches and
   avoid rebuilding the whole GPU buffer when only one tile changes.

The first large-catalog implementation of this plan should stay native-only.
WASM keeps the small embedded HYG subset until a separately generated,
size-capped web subset is documented in the data manifest.

## WASM subset policy

- Default web builds continue using the compact embedded HYG artifact.
- Any Gaia/Tycho/Hipparcos subset for web must be generated by a script with a
  documented magnitude cut, spatial/LOD rule, source version, license, hash, and
  fields used.
- Runtime browser downloads are out of scope for deterministic renders unless a
  session records the exact source artifact and cache identity.
